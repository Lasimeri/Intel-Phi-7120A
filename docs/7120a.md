# The 7120A tree

This checkout (`~/Intel Phi 7120A`) is a copy of the 3120A stack at
cce74b6, changed for one Xeon Phi 7120A in the desktop. The rest of the
documentation still describes the 3120A cards; this page lists what is
different here, what was measured on the 7120A, and what still assumes the
3120A's 57 cores.

## The card

| | 7120A (this tree) | 3120A (the rest of the docs) | Source |
| --- | --- | --- | --- |
| PCI ID | 8086:225c, subsystem 7d99, rev 0x20 (C0) | 8086:225d, subsystem 3c98 or 3608 | `lspci -nn -s 2f:00.0` 2026-10-21; Intel Xeon Phi x100 Specification Update, Table 2-2 |
| Cores, threads | 61, 244 | 57, 228 | `phi run nproc` = 244 |
| GDDR5 | 16 GB, 15872 MiB usable (16384 less 1/32 for ECC) | 6 GB | e820 RAM top 0x3dfffefff from the bootstrap; `MemTotal` 15789924 kB |
| Core clock | 1238 MHz, 1030 mV (`phitop -c 0 --batch 1`, 2026-10-21) | 1.10 GHz ([hardware.md](hardware.md)) | as cited |
| BAR0, BAR4 | 0x7c00000000..0x7fffffffff (16 GiB), 0xfcf00000..0xfcf1ffff (128 KiB) | 8 or 16 GiB BAR0 ([hardware.md](hardware.md)) | `/sys/bus/pci/devices/0000:2f:00.0/resource` lines 1 and 5, 2026-10-21 |
| Link | 5.0 GT/s x8 of a possible x16 (the slot is bifurcated x8/x8) | Gen2 x8 | `current_link_speed`, `current_link_width`, `max_link_width` in the same sysfs directory, 2026-10-21 |
| Board power | 270 W (datasheet 328209 Table 2-1), 280 W (Specification Update), 300 W (ARK) | 300 W ([hardware.md](hardware.md): datasheet 328209 Table 2-1, ARK) | as cited |

Shared device ID: 225c is also the SE10P/SE10X (8 GB) and the 7120X/P/D
(subsystems 7d91, 7d95, 7d9d). `scripts/verify-card.sh` decodes 7d99.

### CPU numbering (measured)

`phi run sh -c 'awk -F": " "/^processor/{p=\$2} /^core id/{c=\$2} /^apicid/{print p, \$2, c}" /proc/cpuinfo'`,
2026-10-21, all 244 CPUs checked (raw: `~/.cache/phi7120a/cpumap-2026-10-21.txt`):

| CPU | APIC ID | Core, thread |
| --- | --- | --- |
| 0 | 240 | core 60, thread 0 |
| 1 + 4k .. 4 + 4k, k = 0..59 | CPU minus 1 | core k, threads 0..3 |
| 241, 242, 243 | 241, 242, 243 | core 60, threads 1..3 |

The same scheme as the 3120A with 61 cores in place of 57: the last core
holds CPU 0 and the three highest CPUs. Patch 0029 places the block-device
pollers from `cpumask_last`, off the last core; measured on this card
(field 39 of `/proc/PID/stat`, 2026-10-21): `phiblk0-poll` on CPU 239 and
`phiblk1-poll` on CPU 238, core 59 threads 2 and 1 (core 55 on the 3120A).

### Boot (measured)

- Bootstrap after `phictl --card 0 reset --timeout 300`, 2026-10-21
  (`~/.cache/phi7120a/reset-*-2dimm.log`): POST "30" (memory training) at
  0.362 s, "3F" (finalize) at 9.073 s, "12" (ready) at 12.090 s, BSP
  APIC ID 240. The 3120A was ready after 9.30 s with its BSP at APIC ID 224
  (`results/2026-09-13-reset-2.md`); `READY_TIMEOUT_MS` is 30000 here.
- `phi up` (phi@0) to a reachable agent: 23.24 s (2026-10-21 23:43,
  `~/.cache/phi7120a/up-234317.log`); 23.18 s through `scripts/phi-up.sh`
  the first time (18:20).
- An earlier stall at POST "30" for 300 s came from a failing host DIMM,
  not the card: training passed once the bad modules were pulled.

## What this tree changes

- `host/asm/phictl/defs.inc`: `PCI_DEVICE_7120` 0x225c, `GDDR_BYTES`
  16 GiB, `READY_TIMEOUT_MS` 30000 (used by `boot.S`, `main.S` peek,
  poke, fill). `sysfs.S` accepts 225c; `card.S` messages name the 7120.
- `host/asm/phitop/view.S`: header "Phi 7120A".
- Scripts: `lspci -d 8086:225c` in `bind-vfio.sh`, `phi-wait-vfio.sh`,
  `phi.sh`, `phi-install.sh`, `verify-card.sh`; `setup-arch.sh` writes
  `ids=8086:225d,8086:225c`; `bind-vfio.sh` refuses any device that is not
  225c or 225d (a slot whose card lost its link handed 2f:00.0 to the GPU).
- `phi vpu` looks for the C co-processor repository (`Intel Phi AVX-512 C`)
  before the frozen assembly one.
- `toolchain/env.sh`: the space-free alias is `~/.cache/intel-phi-7120a`
  and the build root `~/.cache/intel-phi-7120a-build`; a build link that
  points anywhere else is pointed back. The 3120A checkout keeps
  `~/.cache/intel-phi-3120a[-build]`. The 7120A build root started as a
  reflink copy of the 3120A one (2026-10-21; 16 GB apparent, 219 MB used).
  The copy's configured build directories still name the 3120A paths
  (`kernel/out/Makefile`; CMake and Make files under `toolchain/llvm-build`,
  `llvm-build-card`, `compiler-rt-build`, `libcxx-build`,
  `libunwind-build`, and `userland/` dropbear, fastlanes, ncurses, Python,
  xz): rebuild any of those clean here, never incrementally, or the build
  writes into the 3120A root. The initramfs build has no such paths.
- `card/initramfs/etc-skel/fastfetch.jsonc`: 7120A, 61 x 4 = 244.

## Images

- Kernel: the 2026-09-22 11:38 bzImage, unchanged. Its version reads
  `7.2.3-00029-g3368ca98a6e0-dirty` but it carries all 30 patches: the
  tree's 30 commits match `card/kernel/patches/*.patch` by `git patch-id`,
  and the two files of patch 0030 were last written at 11:37:31 and
  11:37:55, before the image (the commit followed at 11:45).
- Initramfs: rebuilt 2026-10-21 from this tree (the 2026-09-29 image is
  kept as `initramfs-2026-09-29.cpio.gz`). Same 445 entries; `init` gains
  cce74b6's swap beside the co-processor's window, the fastfetch
  configuration names the 7120A, os-release carries the date.

## Host memory

`~/.config/phi/cards` gives this card 2G of host memory: below 4 GiB the
region is all swap (2097148 kB measured), which the co-processor turns off
when it starts. At 4G or more the card gets the co-processor's window and
2 GiB of swap beside it, which is what the rack's cards run. The host has
31 GiB.

## Still assuming 57 cores: the AVX-512 co-processor

The C co-processor repository (`Intel Phi AVX-512 C`, db092f6) is not
changed by this tree. Its card worker and scripts are sized for the 3120A
and need the core count from the card at run time (the rack's 3120As run
the same worker):

| File | Assumption |
| --- | --- |
| `card/vpu/defs.inc` | `NCORES` 57, `MAX_POOL` 227, "CPU 0 is core 56" |
| `card/vpu/worker.S` | `max_threads` 57, thread cap 228, the dispatcher on core 56 |
| `card/vpu/rows.S` | slices divided by 57 |
| `card/vpu/matmul.inc` | `POOL_SLOTS` 114 |
| `card/vpu/resident.S` | `WD_SLICES_MAX` 110 (two threads on each of 55 cores) |
| `card/vpu/sched.S` | core 56 the dispatcher's, core 55 the block pollers' |
| `host/asm/phi512/card.S` | `PHI512_THREADS` default 114 |
| `scripts/phi-vpu.sh` | `threads_default` 114, 768 huge pages |
| `scripts/phi512.sh`, `scripts/gates.sh`, `scripts/bench/common.sh` | `start 57`, `-C 55` |

Measured mismatch: the worker treats CPU 0 as core 56 and keeps core 55
for the block pollers; on this card CPU 0 is core 60 and the pollers run
on core 59. How the 57-core worker behaves on this card has not been run.
